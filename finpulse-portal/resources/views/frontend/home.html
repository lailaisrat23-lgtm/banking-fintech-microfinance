Security and responsible finance

Principles behind the demonstration

A financial interface has to earn trust. These are the rules the demo applies to itself, and the limits it states openly.

No credentials, ever

The demo never asks for a bank password, PIN, OTP, card security code or wallet login.

No real transactions

No payment gateway, account or disbursement connection exists. Every status is text in a static page.

Limits stated plainly

Client-side validation is labelled as a convenience, not as secure server-side verification.

Affordability before ambition

Repayment examples include total cost and warn against borrowing more than cash flow can support.

Illustrative, not advice

Educational content is general information and does not replace advice from a qualified professional.

Built for low-bandwidth devices

Local SVG assets, system fonts and simple layouts keep the demo usable on modest phones.
