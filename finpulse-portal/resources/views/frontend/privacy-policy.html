1. Who we are

FinPulse is a fictional brand used to demonstrate a front-end design. There is no company, no registered address, no licence and no data controller behind it. References to "we", "us" and "our" in this document refer to the fictional operator of the demonstration.

2. What this demonstration collects

Nothing. The site is a set of static HTML pages, one stylesheet and local JavaScript modules. There is no backend, no database and no server-side logging of user input.

  • No account registration exists.
  • No personal data is transmitted or stored.
  • No financial information is requested.
  • No PINs, passwords, one-time passwords or card security codes are ever requested.

3. Cookies and analytics

The demonstration sets no cookies and uses no analytics, advertising pixels, session recording, fingerprinting or tracking of any kind. No third-party scripts are loaded.

4. Third parties

All assets are stored locally in the project. No content delivery network, font service, image host or payment provider is contacted when the site loads. Images are local SVG files drawn for the demonstration.

5. Enquiry form data

The contact page contains a form for demonstration purposes. When it is submitted:

  • Values are read by JavaScript running in your browser.
  • They are validated against simple rules such as required fields and email format.
  • A confirmation message is displayed.
  • The values are then discarded. They are never written to a network request, local storage, session storage or a cookie.

You should still avoid typing real financial details into any demonstration form.

6. Retention

Because nothing is collected, there is nothing to retain. If a real service were built from this design, it would need a defined retention schedule for each category of data, including application records, transaction records and support correspondence.

7. Your rights

In a real deployment, individuals would typically have rights to access, correct, delete, restrict and port their data, and to object to certain processing. This demonstration has no data to act on, so there is nothing to request.

8. Security

The demonstration does not store data, so it has no data-security surface beyond the static files themselves. Any real financial service would need encryption in transit and at rest, access controls, audit logging, incident response procedures and independent security testing.

Client-side validation in this project is a usability feature only. It must never be presented as a security control.

9. Changes to this policy

This draft is illustrative and will not be updated. A real policy would record a version history, an effective date and a description of each material change.

10. Contact

There is no data protection officer and no privacy mailbox behind this demonstration. The placeholder address in the footer is not monitored: hello@finpulse.example.

Reminder: this document is a sample for design review. It is not a legally valid privacy policy and must not be published as one.
